How AppMeta Pulse
talks to App Store Connect.

AppMeta Pulse authenticates to App Store Connect using Apple's official API with a key you generate in your own account. This page documents exactly which endpoints the app calls, which API key role is required for each, how the short-lived JWT tokens are signed and refreshed, where credentials live, and — equally important — what the app cannot do because of the scope it operates under. No marketing language. Verifiable against Apple's own documentation.

What you generate, what the app stores.

App Store Connect API keys are generated in your App Store Connect account, not by AppMeta Pulse. The app cannot generate or escalate a key; it can only use the one you give it.

In App Store Connect (you)
  • Sign in to App Store Connect with an account that has permission to create API keys (Admin or Account Holder).
  • Open Users and Access → Integrations → App Store Connect API.
  • Generate a new key with the Admin role. AppMeta Pulse asks for Admin because it is the role that covers sales reports, App Analytics, and review replies together; App Manager and Developer keys can't read sales reports, and Apple answers them with a 403 error.
  • Download the .p8 private key file. Apple only lets you download it once — if you lose it, you regenerate.
  • Copy the Key ID (10-character string) and the Issuer ID (your team's UUID, shown above the keys list). Pulse also needs your Vendor Number from Payments and Financial Reports to download sales reports.
In AppMeta Pulse (the app)
  • Paste or import the .p8 file, Key ID, and Issuer ID into AppMeta Pulse.
  • The three values are stored together in the system Keychain — the same secure storage iOS and macOS use for passwords and Wi-Fi credentials.
  • None of the three is written to plain files, iCloud Drive, iCloud Sync, third-party servers, or analytics SDKs. With iCloud Sync on, the Issuer ID is replaced by a one-way hash and the Key ID by a short hash; the account name and vendor number you entered do sync.
  • Revoke the key any time in App Store Connect → Users and Access → Integrations. Revocation takes effect at Apple's API immediately; the app cannot circumvent it.

How the request is actually signed.

Per Apple's documented requirements for API tokens, every request to the App Store Connect API must include a short-lived JSON Web Token signed with ES256 using your private key. AppMeta Pulse does this signing locally — the .p8 private key never leaves your device.

01
Token construction
Header: alg: ES256, kid: <your Key ID>, typ: JWT. Payload: iss: <your Issuer ID>, iat: <now>, exp: <now + ≤20 min>, aud: appstoreconnect-v1. Apple's documentation specifies a maximum token lifetime of 20 minutes — tokens with longer expiry are rejected by the API.
02
Signing
The token header + payload is signed locally with the ES256 algorithm using your .p8 private key. The signing happens on-device; the private key bytes never go to a network. Apple's API verifies the signature using the public key registered against your Key ID.
03
Request
The signed JWT is attached as an Authorization: Bearer <token> header on each HTTPS request to https://api.appstoreconnect.apple.com. The request goes directly to Apple — no intermediate proxy, no Lagerland server, no third-party analytics endpoint.
04
Refresh
When the JWT is close to expiry, AppMeta Pulse generates a new one from the same stored Key ID, Issuer ID, and .p8 — same construction, new iat and exp. There is no refresh token in the OAuth sense; Apple's API uses self-signed short-lived JWTs only.

Endpoints called, and the role they need.

AppMeta Pulse asks for one key with the Admin role, because that role covers everything below. Apple's role permissions decide what a key can reach; when a request is refused, Settings → Connection in the app shows which data source failed and why.

Sales and Trends reports
Endpoint: GET /v1/salesReports with report type SALES, daily (and yearly for the By Year chart), using your Vendor Number. Returns units, customer price, and developer proceeds per product and territory.

Role: Admin. App Manager and Developer keys can list your apps but can't download sales reports; Apple answers them with a 403 error, and the app says so at sign-in.

This is the endpoint that drives the proceeds, sales, downloads, and territory views.
Subscription reports
Endpoint: GET /v1/salesReports with report types SUBSCRIPTION and SUBSCRIPTION_EVENT, daily.

Role: Admin, as for the Sales report.

Drives the subscription views — MRR, active subscriptions, trials, trial-to-paid conversion, churn, and cancellations.
App Analytics
Endpoints: GET on /v1/apps/{id}/analyticsReportRequests, the reports, instances, and segments under it, plus the time-limited download links Apple returns; and POST /v1/analyticsReportRequests for an app that has no request yet (an ongoing one, plus a one-time snapshot for history on the first sync), which asks Apple to start preparing the reports.

Role: Admin. With a key that lacks it, Pulse skips analytics for that app and reports it in Settings → Connection.

Drives impressions, product page views, and the App Store conversion funnel.
Catalog and customer reviews
Endpoints: GET /v1/apps, each app's in-app purchases and subscription groups, and GET /v1/apps/{id}/customerReviews with any developer responses.

Role: a key that can't post replies can still read reviews; replying needs Admin, and the app asks for an Admin key when a reply is refused.

Drives the app list, product names, and the reviews screens.
Endpoints AppMeta Pulse does NOT call
No build submission endpoints. No app metadata edit endpoints. No pricing endpoints. No TestFlight management endpoints. The app writes to App Store Connect in exactly two places: POST, PATCH, and DELETE on /v1/customerReviewResponses when you send, edit, or delete a review reply, and POST /v1/analyticsReportRequests, which asks Apple to start preparing your analytics reports.

What the app can and cannot change.

Two layers of limits — what the app's code does, and what your key's role allows.

At the app level
  • The network layer reads with GET. Its only writes are review replies you send (POST, PATCH, DELETE on customer review responses) and analytics report requests (POST). There is no code for builds, metadata, pricing, or TestFlight.
  • The UI has no "submit," "publish," metadata, or pricing controls. The only buttons that change App Store Connect are Reply (to one review or a batch of up to 25), Edit, and Delete on your own review responses.
  • Pushing the wrong build or hiking the wrong price is impossible inside AppMeta Pulse by construction.
At Apple's API level
  • The role you set on the API key determines what the key can do. An Admin key could change far more than Pulse ever asks of it, so the limits on what Pulse changes are the code limits listed on the left, not the key's role.
  • You can revoke the key in App Store Connect at any time; the next API call from AppMeta Pulse will fail with 401 and the app surfaces that state clearly.
  • Apple's API enforces the role at the request level — not on trust of the calling app.

Data freshness — what to expect.

App Store Connect's own reporting cadence is the upper bound on freshness; no third-party dashboard can be faster than Apple's source data.

Sales and Trends
Apple publishes each day's report the following day, generally by 8 a.m. Pacific Time (Apple). Same cadence as the App Store Connect web dashboard; App Store analytics arrive a day or two later. AppMeta Pulse checks in the background about hourly until the new day is in, and again when you open the app or pull to refresh; the data shown is whatever Apple has currently published for your account.
Financial Reports
Apple publishes monthly Financial Reports after each fiscal month closes. These are the canonical reconciliation source for tax filing and accounting. AppMeta Pulse only reads Sales and Trends figures (next-day), not Payments and Financial Reports; for tax filing, reconcile against Apple's monthly downloadable Financial Reports.

What we deliberately do not promise.

Honest limits
  • Numbers can never be fresher than Apple's reporting cadence. We cannot accelerate Apple's overnight ETL.
  • Pulse converts every amount into your display currency with the European Central Bank's monthly average rates. Apple pays with its own exchange rates and after withholding and bank fees, so converted totals will not match what hits your bank account.
  • If your API key's role can't read a data source (an App Manager or Developer key can't download reports), Settings → Connection says which one failed and why, rather than showing empty charts silently.
  • App Store Connect API rate limits are managed by Apple. Heavy refresh during a sales spike may briefly throttle; the app backs off rather than retrying aggressively.
What is genuinely under our control
  • Where the .p8 key lives (system Keychain — not iCloud Drive, not a plaintext file, not a third-party server).
  • Where your data goes when iCloud Sync is on (your own private iCloud database, which we can't access; the .p8 key never syncs).
  • What the app does with your data after fetching it (keeps it for you — nothing is sent to us, and the App Store privacy label declares zero data collection, verifiable on the listing).
  • Which App Store Connect writes the app makes (only the review replies you send and analytics report requests, listed above).
  • Honest disclosure when something changes (this page is dated and updated when the model changes).
